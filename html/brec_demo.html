How this differs from real training

Policy

  • A practice-driven per-cell competence field, not a PPO-trained goal-conditioned network. No observations, no actions, no gradient steps — competence rises simply because a policy-branch episode visited a cell.

Rollout

  • A turn-rate-limited geodesic-gradient follower over a BFS distance field. No rigid-body physics, no contacts, no falling/termination reward terms.

Reward

  • Normalized geodesic progress in [0,1], so r_min/r_max live on that scale here — not the parkour reward-term sum, where the shipped preset's r_max=50.0.

State

  • The agent carries a heading in addition to its position, and the start-side novelty key uses it — so the space starts are stored in is strictly larger than the 2-D (x, y) subspace used for nearest-neighbour search, mirroring parkour's 18-D init_subspace against 3-D xyz goals. Heading is no longer drawn, to keep the canvas readable.

Achieved start

  • Identical to the commanded start here, because there is no physics settling step. In the real system the two differ by one integration step (see gc_cure.md §6) — which is precisely why the real code re-derives it from the trajectory instead of assuming it equals the commanded value.

Iteration order

  • This demo runs walk-seed-selection/walks/harvest before branch-assignment/rollout/band-split within each iteration, for a more linear "explore first, then plan" narrative. The real system interleaves both — it harvests the previous call's walks and episodes at the top of every call, then assigns new starts/goals for whichever envs are resetting — and every iteration here resets all configured envs synchronously in five explicit phases, unlike the real system's fully asynchronous per-env resets.

Vectorization

  • The real system batches every operation as tensor ops across hundreds of parallel envs (PyTorch, FAISS). This demo loops per-env in plain JavaScript with a brute-force nearest-neighbour search. The semantics match; the performance characteristics don't.

Scale & fixed knobs

  • The reward bands, novelty thresholds, the replay ratios, the competence-model parameters and the RNG seed are fixed rather than exposed, to keep the controls focused on the branch-mode and walk-seeding story. The replay ratios match the shipped preset (goal_replay_ratio=0.4, start_replay_ratio=0.0).

update_interval

  • The mixed buffers rebuild every iteration here; the real system rebuilds on an interval measured in environment steps. With thousands of parallel envs the buffers refill fast enough that the staleness never shows, but at this demo's scale a multi-iteration freeze pins the walk-seeding pool to a handful of entries and makes voronoi selection look degenerate — it keeps returning the same seeds simply because there is nothing else in the buffer to return.

select_knn, and why it is 1 here

  • get_similar takes the select_knn nearest buffer entries to the query and then picks uniformly among them — a deliberate softening that buys seed diversity. The shipped presets use 4. This demo uses 1, making voronoi selection exact nearest-neighbour, i.e. textbook Voronoi-cell-proportional sampling: an entry is drawn with probability equal to the share of free space closer to it than to any other entry. At the buffer sizes here (tens of entries, not thousands) a top-4 uniform pick is visually indistinguishable from picking at random, which hides the mechanism the demo exists to show.

Bootstrap seeding

  • Walk-seed selection reads the mixed buffers as they stood at the start of the iteration, and those are empty on iteration 1 — so the first iteration performs no voronoi selection at all, in either direction. Every seed is a fixed bootstrap spawn, drawn without an attractor marker because no selection took place.
  • The forward bootstrap is the start region, matching the real code. The backward bootstrap is the goal itself, which is a deliberate divergence: the real fallback is also the initial-state sampler, so a backward walk with nothing proven yet starts in the start region while recording the goal as its inherited goal. That is survivable at training scale, where the mixed buffer fills within a few calls, but it reads backwards in an explainer and it self-propagates here — those walks fill start_candidate with states nowhere near the goal. The reverse-curriculum bootstrap already establishes the goal as a known-good start, so the demo falls back to it.

Coverage bookkeeping

  • Coverage is recorded as a persistent "ever proven" bitmap, so a cell stays shaded once proven. The real buffers are finite and ring-evicting, so an entry that first proved a cell can later be dropped — the underlying buffers here behave the same way, but the display does not flicker with them.

Ablated away

  • The reachability branch, the greedy seed mode, and the runner-side walk-tail split (random_reachability_ratio) are absent — matching the no-reachability arm this demo targets. The forward/backward walk split is derived from which branches are active, so a single-direction mode never spends walk envs on the inactive direction.

Standing assumption

  • The competence model makes sub-skill composition nearly automatic: once every cell on a path is practiced, a rollout crossing it succeeds unless the finite horizon or a per-step stall intervenes. This mirrors the algorithm's own premise — that a goal-conditioned policy which has separately mastered two adjoining regions can chain them — rather than proving it independently.
